# Rouse — page art direction

Phase 16 / 2026-11-08. Product Lock revision 1 and the user-locked Rouse name control. Phase 15 identity: retained-counter r, outlined wordmark, Trace Instrument palette and type roles.

**Selected direction: Working Precedent.** Current chain evidence and prior reviewed judgment occupy one working canvas. The resolution is useful because its origin, compatibility and limits remain inspectable.

This is a composition contract before application-wide implementation. It does not set DESIGN_LOCK, FULL_PRODUCT_VERIFIED or JUDGE_READY, and does not deploy a renamed app.

## A. Product reality

User: Sui dApp/protocol engineer or ecosystem support responder, starting with one operator-managed shared case space.
Job: inspect an actual failed execution, compare a compatible reviewed resolution, and preserve a new resolution when a human has evidence for it.
Emotional promise: avoid reconstructing an investigation from zero while retaining enough context to make an engineering judgment.

First 30 seconds: understand “resolution memory for Sui engineers”; inspect a transaction or open the reviewed example; see the failed outcome beside a concrete earlier procedure.
Signature moment: a distinct real failure recalls the exact reviewed Walrus blob. The evidence is visible alongside the procedure; the interface never implies automatic repair.

Primary public action: Inspect a transaction.
Secondary public action: Open reviewed example.
Workspace primary action: Inspect transaction.
Reviewer secondary path: Record a reviewed resolution; protected by existing authorization and proof validation.

## C. Composition contract

### Landing first fold

- Goal: make retained resolution value tangible before asking for trust.
- Focal point: one stable recorded-precedent canvas, not two floating/rotated cards.
- Primary asset: a faithful reconstruction from the actual approved cancellation record, its distinct later failure and exact blob. Label as a recorded example, never live telemetry.
- Desktop: max 1344px outer width; 48px gutters; approximately 41:59 copy/example split; 62px gap. 64px headline,16px body. Keep both example identity and primary action visible.
- Story: general resolution-memory promise on the left; one bounded engineering example on the right. The example is supporting proof, not a DeepBook-only product.
- Counterweight: simple left-aligned wordmark and narrow navigation; no glow, rings, grids or decorative blockchain imagery.
- Copy/visual: “The next failure shouldn't start from zero” is supported by two distinct source IDs, a named reviewer and the same retained blob.
- Entrance/scroll: content visible immediately; no entrance gate or scroll hijack. Restrained response transitions may be added after motion acceptance.
- Mobile: 22px gutters; 46px headline; promise/action first, case canvas next. No horizontally cropped console image. IDs wrap.
- Meaning: the system retains reviewed reasoning and source evidence, not merely an error string.

### Landing method and proof

- Goal: explain the real journey without a generic feature-card wall.
- Focal point: three ruled task rows—inspect, preserve reviewed resolution, recall for the next investigation.
- Asset: real terminology and a compact exact-record proof block. No fabricated testimonials or impact statistics.
- Desktop: supporting heading left, sequential rows right; proof block spans content width below.
- Mobile: one column; preserve order, labels and evidence link. No large decorative manifesto section.
- The original-operator deployment limit sits next to the example, not buried in a footer.

### Workspace and signature moment

- Goal: help the engineer assess whether prior reasoning applies to this failure.
- Focal point: procedure and failed evidence at comparable visual weight.
- Desktop: compact 30px task title, full-width digest intake, then roughly 43:57 evidence/precedent columns with 28px gap.
- Chain side: current digest/outcome/source facts, orange normalized error, explorer link, raw execution error disclosure.
- Memory side: reviewed procedure first; match dimensions; unknown-current-SDK warning; original deployment limit; reviewer/evidence link; exact blob strip; full provenance disclosure.
- Mandatory first-fold target: at 1440×900, the procedure, reasons, reviewer and entire exact-blob strip are visible. Final production QA must repeat this without prototype metadata.
- Mobile: intake → chain facts → reviewed procedure → reasons/limits → exact blob → optional provenance. No sticky action overlay over evidence or the software keyboard.
- Do not add an “apply fix” button or mark the new incident resolved. Candidate eligibility remains a suggestion for engineering review.
- Positive matches use lime sparingly; execution failure uses orange; unknown/pending remain neutral.

### Reviewer and receipt compositions

- Keep review as a deliberate secondary action after inspecting evidence; it is not the landing hero.
- Preserve both proof routes and every existing required field: diagnosis, concrete procedure, exact engineering change, proof method, artifact URL/verification method or successor digest, reviewer, optional SDK and explicit causal/reuse approvals.
- No prefilled diagnosis, named reviewer or approval checkbox. Changing proof method must expose its corresponding fields.
- Pending shows accepted job identity without a completed blob. Ambiguous response blocks another submission and preserves the attempt.
- Completed receipt shows source digest, job and exact blob. Another lookup/mismatch cannot visually erase it.
- Observation receipts explicitly say no resolution claim. Do not repurpose this composition to upgrade evidence tiers.

### Field notes and proof surfaces

Keep body text readable, source/evidence links adjacent, long identifiers wrapped and historical wording dated. Rouse branding may change, but immutable GitHub/Walrus/source links retain their names and URLs. The older flashloan experiment remains separate, not a featured repaired case.

## D. State grammar and P0 preservation

| State | Visual / action contract |
|---|---|
| Empty | Digest input plus sample entry; no fabricated rows |
| Unconfigured | Setup guidance and disabled lookup; no secret values in copy |
| Loading | Name the read in progress; clear earlier suggestions; bounded request behavior retained |
| Lookup error | Gateway/read failure, not failed execution; retry lookup |
| Successful execution | Show success; do not recall a failure procedure or infer causal repair |
| Unknown outcome | Neutral state; no failed classification, recall or reviewed write |
| Failed, no eligible match | Keep chain evidence; explain unresolved status; reviewer path remains protected |
| Recall unavailable | Keep chain evidence; explicitly state no conclusion about saved cases; read-only retry |
| Eligible precedent | Procedure, matching reasons, uncertainty, reviewer/source/blob |
| Review | Blank fields and explicit human judgment; keep server validation |
| Accepted / pending / ambiguous write | No completed receipt; read existing job; never auto-repeat a write |
| Completed write | Real receipt only; preserve source and exact blob across further work |
| Recurrence mismatch | Explain mismatch; preserve valid storage receipt |
| Lower evidence tiers | Separate observation/runbook labels; never visually mark as human-reviewed |

Prototype renders 12 states at desktop/mobile; remaining substate behavior inherits the Phase 14 verified workflow and is mandatory for implementation QA.

## E. Asset, type and motion inputs

Assets: canonical Rouse wordmark/favicon; actual public case data; source-backed screenshots after implementation. No generated product screenshot, stock hero, fake console, sponsor-mark recreation or invented live service dots.

Type: self-host Space Grotesk headings, DM Sans reading text and DM Mono provenance using the supplied kit. Prefer 12–14px provenance/body labels over decorative 9px uppercase text. Keep digests copyable/wrapping; source data stays accessible as text.

Palette: ink#0e1212; surface#17201c; paper#f5f5ef; recalled/action#c8ed9b; failed#ef8b6e; muted#a1aaa5. Color always has a text equivalent.

Signature motif: one restrained retained edge/counter interruption if it supports a source relationship. Do not repeat the r shape as a wallpaper or create false connectors between unrelated incidents.

Motion input: request state changes in place; no fake staged success. Proposed response durations 160–200ms, no forced stagger. Controlled loading indicator is demonstrated; its pseudo-element animation is explicitly disabled under reduced motion. Production read → recall → stored → reuse state sequences still need the Phase 19 storyboard and Phase 22 motion checks.

Accessibility: primary actions at least 44px high; mobile supplemental links/disclosures 44px; visible focus; semantic headings/labels; no toast-only receipts; no horizontal identifier scrolling; no decorative motion required for understanding.

Performance input: logo SVGs have no font dependency; self-host the three font families; avoid new illustration/video dependencies. Lazy-load only below-fold media. No new data requests for decorative displays.
