## Reproduction

Use the existing private server environment without logging values. From repository root, set `ROUSE_ACCEPTANCE_BASE=https://casewake.vercel.app`, then run `web/scripts/phase25-api-adversarial.mjs`, `verify-phase23-live.mjs` and `phase25-public-assets.mjs` with explicit Phase25 output paths. They perform reads and guaranteed pre-write rejections. Never submit a well-formed observation or approved resolution as an audit fixture.

`python scripts/prepare-phase25-browser.py --base https://casewake.vercel.app` creates CLI wrappers for actual and controlled browser suites. Use a fresh browser context for actual evidence; fixture init scripts must never contaminate actual screenshots. `scripts/collect-phase25-browser.py` rejects CLI error blocks. `python scripts/verify-proof-registry.py --require-fresh` validates current dispositions, hashes, source binding and the recorded checks; it does not refresh live services.

One early accessibility run was contaminated by the QA label in a reused context; a later receipt-label init script caused a fixture-only hydration mismatch. Both harness issues were corrected and rerun in isolated contexts. Neither failure was discarded as a product pass. Actual public runs and final controlled runs contain zero client JavaScript errors.
